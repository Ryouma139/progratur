## YAMLとは

**YAML** は、人間が読み書きしやすいことを重視して設計された**データシリアライゼーション形式**です。設定ファイルや、処理手順を記述する「プレイブック」形式のファイルによく使われます。

拡張子は `.yaml` が正式ですが、`.yml`（3文字の拡張子に揃えた慣習）もまったく同じ形式を指し、どちらも広く使われています。

## JSONとの違い

同じ構造を持つデータを、JSONとYAMLでそれぞれ書くと次のようになります。

```json title="JSON"
{
  "name": "progratur",
  "languages": ["csharp", "java", "python"],
  "settings": {
    "darkMode": true,
    "postsPerPage": 10
  }
}
```

```yaml title="YAML（同じ内容）"
name: progratur
languages:
  - csharp
  - java
  - python
settings:
  darkMode: true
  postsPerPage: 10
```

JSONは中括弧 `{}` や角括弧 `[]` で構造を明示するのに対し、YAMLは**インデント**によって階層構造を表します。波括弧や引用符を書かずに済む分、設定ファイルとして人間が読み書きする分には視認性が高くなります。一方で、インデントのスペース数やタブ混在のミスが構造そのものを壊してしまう、という弱点にもなります。

## 基本構文

### マッピング（キーと値）とシーケンス（配列）

```yaml
# マッピング: key: value
title: Progratur

# シーケンス: 先頭に "- " を付ける
languages:
  - csharp
  - java
  - python
```

YAMLのデータは大きく「コレクション」（シーケンス＝配列、マッピング＝キーと値のペア）と「スカラー」（文字列・数値などの単一の値）に分類されます。`:` がキーと値の関連付け、`-` が配列要素を表す、という2つの記号がYAML構文の基本です。

### ネスト（入れ子構造）

```yaml
presets:
  blog:
    path: blog
    routeBasePath: blog
    postsPerPage: 10
```

インデントを1段深くすることで、親キーの下にぶら下がる構造を表現します。インデントの深さがそのまま階層の深さになるため、スペースの数を途中で変えてはいけません（タブ文字も使用不可とされています）。

### 複数行文字列

長い文字列を書くための記法が2種類用意されています。

```yaml
# "|" : 改行をそのまま保持する
description: |
  1行目です。
  2行目です。改行がそのまま残ります。

# ">" : 改行をスペースに変換して1行に折りたたむ
summary: >
  これは長い説明文ですが、
  複数行に分けて書いても
  最終的には1行に結合されます。
```

`|` は改行を維持したいとき（コマンドの複数行スクリプトなど）、`>` は見た目だけ折り返して実際は1つの文として扱いたいときに使い分けます。

### コメント

```yaml
# "#" から行末まではコメント
name: progratur # 行末コメントも書ける
```

## どこで使われているか

YAMLは設定ファイル全般で広く採用されており、代表的な例は次の通りです。

| 用途 | 例 |
| --- | --- |
| CI/CDパイプライン定義 | GitHub Actionsの`.github/workflows/*.yml`、GitLab CIの`.gitlab-ci.yml` |
| コンテナオーケストレーション | Kubernetesのマニフェストファイル |
| 構成管理 | Ansibleのプレイブック |
| アプリケーション設定 | 各種フレームワークの設定ファイル、プロセス間のメッセージ共有など |

GitLabでは、プロジェクトごとに`.gitlab-ci.yml`を1つ用意し、そこにパイプラインの構造（どのジョブを、どの順番で、どのステージで実行するか）を定義して GitLab Runner に処理させる、という使い方をします。GitHub Actionsにおける`.github/workflows/*.yml`も考え方は同じです。

## YAMLが好まれる理由と注意点

YAMLが設定ファイルの定番になっている理由としては、次のような点が挙げられます。

- 波括弧や引用符が少なく、人間にとって読みやすい
- Pythonのインデントに近い感覚で階層構造を書ける
- 文字列・数値・真偽値・配列・マッピングなど複数のデータ型を表現できる
- 主要なプログラミング言語のほとんどにパーサーが存在する

一方で、前述の通り**インデントの崩れがそのまま構文エラー・意味の変化につながる**点は弱点です。タブとスペースの混在、インデント幅のズレは、YAMLを書く上で最も事故が起きやすいポイントなので注意が必要です。

## まとめ

YAMLは「インデントで階層を表す」というシンプルなルールの上に、マッピング・シーケンス・複数行文字列などの表現力を載せたフォーマットです。CI/CDやコンテナ関連の設定ファイルで触れる機会が多いため、`:` と `-` とインデントの3点さえ押さえておけば、初見の設定ファイルでも構造を読み解きやすくなります。
