# コードエディター（Playground）機能の追加（2026-09-16）

このドキュメントは、2026年9月16日に行った `progratur/` への「コードエディター」機能（ブラウザ上でPython/Java/C#のコードをサンドボックス実行できる機能）の追加についてまとめたものです。

## 概要

ヘッダーナビバーに「コードエディター」項目を追加し、`/playground` で以下ができるようにした。

- Python / Java / C# のコードをブラウザのエディターに書く
- 「実行」ボタンで外部の使い捨てサンドボックス環境にコードを送信し、結果（標準出力・標準エラー出力・コンパイルエラー・実行時間・メモリ）を表示する
- 標準入力（stdin）を指定して、`input()` / `Scanner` / `Console.ReadLine()` を使うコードも試せる

このサイトはバックエンドを持たない静的サイト（Docusaurus）のため、コード実行そのものは自前実装せず、外部の公開コード実行API（Judge0 CE）に委任する設計にした。

## サンドボックス方式の検討

最初に3つの実現方式を検討し、ユーザーと相談のうえ「外部実行APIを利用する」方式を採用した。

1. **外部実行API（採用）**: 無料の公開APIにコードを送信し、サーバー側のコンテナでサンドボックス実行。多言語対応・バックエンド構築不要。ただし外部サービス依存
2. **ブラウザ内WASM実行**: PythonはPyodideで実現可能だが、Javaは実用的な選択肢が乏しく、C#も.NET WASMは重量級。3言語を揃えるのが難しいため見送り
3. **JavaScript限定でiframeサンドボックス**: サイトの主要言語（C#/Java/Python）を実行できないため見送り

配置場所も検討し、「独立した新規ページ（`/playground`）」を採用（doc各ページへの埋め込みは見送り）。

## 実装

### 追加ファイル

- [src/pages/playground/index.js](src/pages/playground/index.js) — ページ本体。`<BrowserOnly>`（`@docusaurus/BrowserOnly`）で中身をクライアント限定レンダリングし、SSR時にfetch/DOM依存コードが評価されないようにしている
- [src/pages/playground/Playground.js](src/pages/playground/Playground.js) — エディター本体。言語切替タブ、コードエディター、stdin入力、実行/リセットボタン、結果表示を実装

### 追加パッケージ

```json

```

`prismjs` は `prism-react-renderer`（既存依存）の内部依存として既に存在していたため、実質的な新規追加は `react-simple-code-editor` のみ。

## ハマった点・修正した不具合

### 1. prismjsの言語グラマーが登録されない（`The language "python" has no grammar.`）

`import Prism from 'prismjs'; import 'prismjs/components/prism-python';` という定番の書き方をしたが、実行時に `Prism.languages.python` が未定義でエラーになった。

**原因**: prismjsの言語コンポーネントファイル（`prism-python.js` 等）は、`Prism.languages.python = {...}` のように「グローバルに `Prism` が既に存在する」ことを前提にした古い実装になっている。バンドラー（Rspack）の環境では、この「暗黙のグローバル参照」が期待通りのインスタンスに解決されないことがあり、登録に失敗していた。

**対処**: `window.Prism` を明示的に固定してから、`require()` で順番どおりに言語コンポーネントを読み込む形に変更した（[Playground.js:6-15](src/pages/playground/Playground.js#L6-L15)）。

```js
if (typeof window !== 'undefined') {
  window.Prism = Prism;
}
require('prismjs/components/prism-clike');
require('prismjs/components/prism-csharp');
require('prismjs/components/prism-java');
require('prismjs/components/prism-python');
```

あわせて、文法が万一未登録でも例外にならずプレーンテキスト表示にフォールバックするようガードも入れた（[Playground.js:206-209](src/pages/playground/Playground.js#L206-L209)）。

### 2. Piston公開APIがホワイトリスト制になっていて使えない（HTTP 401）

当初は [Piston](https://github.com/engineer-man/piston) の公開API（`emkc.org/api/v2/piston/execute`）を使う実装にしていたが、実行ボタンを押すと `HTTP 401` エラーになった。

**原因**: Piston公開APIは **2026年2月15日から事前ホワイトリスト制** に変更されており、個人・ポートフォリオ用途は明示的に許可対象外とされていた（README記載の "Important Note" より）。この変更は今回の作業中に初めて判明した（知識としては未把握だった）。

**対処**: 代替として以下を調査・実機検証した。

| API | 結果 |
|---|---|
| Piston公開API | ❌ 401（ホワイトリスト制） |
| CodeX API（`api.codex.jaagrav.in`） | ❌ 503（サービス自体がダウン） |
| Wandbox（`wandbox.org`） | ❌ 500（サーバー側の内部エラー、`Failed to get uid`） |
| **Judge0 CE公開インスタンス（`ce.judge0.com`）** | ✅ APIキー不要・CORS許可・Python/Java/C#すべて実行成功 |

最終的に **Judge0 CE** に切り替えた。レスポンス形式がPistonと異なる（`run.stdout` → `stdout`、`compile.stderr` → `compile_output` 等）ため、[Playground.js](src/pages/playground/Playground.js) の言語定義（`judge0LanguageId` を使用）と結果表示部分を全面的に書き直した。

ただし、Judge0 CEも公式のコミュニティ向け無料デモ枠であり、SLA保証はない。将来利用できなくなった場合は、自前でJudge0をセルフホスト（Docker + Docker Compose）する選択肢がある。

## サンドボックス境界の検証

「利用者が任意のコード（`os.system(...)` 等）を実行できる」機能である以上、実際にJudge0 API経由でサンドボックスの境界を検証した。

| 検証項目 | 結果 |
|---|---|
| 実行ユーザー | `uid=12035446` など、ジョブごとに動的採番される非root・無名ユーザー |
| ファイルシステム | `/etc/passwd` 等の一般的な読み取り専用システムファイルは閲覧可能。`/box`・`/tmp` はジョブ専用UIDの `0700` 権限で他ジョブから隔離 |
| ネットワーク | `urllib.request.urlopen()` は `Temporary failure in name resolution` で完全にブロック（DNS解決すら不可） |
| 環境変数 | 機密情報の漏洩なし（Judge0自体のconda環境パス・バージョン情報のみ） |

このサイト自体はバックエンドを持たない静的サイトのため、そもそもコード実行はJudge0側のコンテナ内で完結し、このサイトのサーバーには一切到達しない。ネットワーク遮断も確認済みのため、`os.system("rm -rf /")` のような破壊的コマンドを打っても影響範囲はJudge0側の使い捨てコンテナ内（かつネットワークなし）に閉じる。

## 動作確認（手動テスト用サンプル）

`/playground` で以下を貼り付けて動作確認できることを確認した。

**stdin（Python）**
```python
name = input()
age = input()
print(name + " is " + age + " years old")
```
stdin: `Taro` / `25`

**stdin（Java, Scanner）**
```java
import java.util.Scanner;
public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String name = sc.nextLine();
        int age = Integer.parseInt(sc.nextLine());
        System.out.println(name + " is " + age + " years old");
    }
}
```

**コンパイルエラー（Java, セミコロン抜け）** → `Compilation Error` になることを確認

**実行時エラー（Python, ゼロ除算）** → `Runtime Error (NZEC)` とトレースバックが出ることを確認

**タイムアウト（Python, 無限ループ）** → `CPU_TIME_LIMIT_SEC = 5` で `Time Limit Exceeded` になることを確認
