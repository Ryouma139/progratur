# ブログ記事のPDF保存機能の追加（2026-09-17）

このドキュメントは、2026年9月17日に行った `progratur/` への「ブログ記事ごとにPDF保存できる機能」の追加についてまとめたものです。

## 概要

各ブログ記事ページ（`/blog/<slug>`）のタイトル直下に「PDFとして保存」ボタンを追加した。クリックするとブラウザの印刷ダイアログが開き、印刷先を「PDFに保存」にすることでその記事をPDF化できる。

このサイトはバックエンドを持たない静的サイト（Docusaurus）のため、jsPDFやhtml2canvasのような追加ライブラリは導入せず、**ブラウザ標準の印刷機能（`window.print()`）+ 印刷用CSS** で実現した。テキスト選択・リンクが保持された本物のPDFがオフラインでも生成できる。

## 実装

### 追加ファイル

- [src/components/BlogPostPdfButton/index.js](src/components/BlogPostPdfButton/index.js) — 「PDFとして保存」ボタン本体。`useBlogPost()`（`@docusaurus/plugin-content-blog/client`）の `isBlogPostPage` を見て、記事ページ（一覧のプレビューカードではない）でのみ表示する。クリックで `window.print()` を呼ぶだけ
- [src/components/BlogPostPdfButton/styles.module.css](src/components/BlogPostPdfButton/styles.module.css) — ボタンの見た目（サイトのプライマリカラーに合わせたアウトラインボタン）
- [src/theme/BlogPostItem/Header/index.js](src/theme/BlogPostItem/Header/index.js) — `docusaurus swizzle @docusaurus/theme-classic BlogPostItem/Header --wrap` でラップし、タイトル直下に `<BlogPostPdfButton />` を差し込んでいる

### 印刷用CSS

[src/css/custom.css](src/css/custom.css) の `@media print` ブロックで以下を行っている。

- ナビバー・ブログサイドバー（最近の記事一覧）・目次（TOC）・サイトフッター・前後記事ページネーション・保存ボタン自体を非表示にし、本文のみが印刷されるようにする
- ダークモードで開いていても、印刷時は `--ifm-background-color` 等のInfima変数を強制的に上書きして白背景・黒文字にする（暗い配色のまま印刷されて読めなくなるのを防止）
- コードブロック（`pre[class*='language-']`）の背景を明るいグレーに固定し、ダークテーマのシンタックスハイライト配色のまま印刷されないようにする
- 記事本文中の外部リンク（`.markdown a[href^='http']`）には `::after { content: ' (' attr(href) ')' }` でURLをテキストとして併記し、リンクとして機能しない環境でも参照先が分かるようにする

## ハマった点・修正した不具合

### 1. `@page { margin: 0 }` でブラウザのヘッダー/フッターを消そうとしたが効果がなく、むしろ本文と重なった

最初、「`@page` のmarginを0にするとChrome/Edgeが付与する日付・URL・ページ番号のヘッダー/フッターが消える」という広く知られたテクニックを採用した。しかし実際には効果がなく、余白がゼロになった結果、ヘッダー/フッターのテキストが本文の端と重なって表示される不具合になった。

**結論**: ブラウザが印刷時に付与するヘッダー/フッターは、**印刷ダイアログの「ヘッダーとフッター」チェックボックス側の設定でのみ**制御されるものであり、サイト側のCSS/JSから無効化することはできない（少なくとも現行のChrome/Edgeでは）。

**対処**: `@page { margin: 0 }` はやめ、`@page { margin: 20mm 15mm }` に変更（[custom.css:64-66](src/css/custom.css#L64-L66)）。ヘッダー/フッターを表示したままでも本文と重ならないよう、通常サイズの余白を確保する方向に変更した。完全に消したい場合は、印刷ダイアログの「詳細設定」→「ヘッダーとフッター」のチェックを外してもらう運用でカバーする。

### 2. Windows「Microsoft Print to PDF」ではPDF内のURLにアクセスできない

「PDF上のURLにアクセスできない」という指摘を受けて確認したところ、**印刷先（プリンター）としてWindows OS標準の「Microsoft Print to PDF」を使っていた**ことが原因と判明した。

**原因**: 「Microsoft Print to PDF」はOSレベルの汎用プリンタードライバーであり、物理プリンターに印刷するのと同じ扱いでページを描画するため、Webページの `<a href>` が持つハイパーリンク情報を保持せずPDF化してしまう。そのため、本物のリンクも、CSSで追記したURLテキストも、どちらもクリック不可になる。

これに対して、**Chrome/Edgeが印刷ダイアログの送信先一覧に自前で用意している「PDFに保存」（Microsoft Print to PDFとは別の選択肢）** を使った場合は、`<a href>` がクリック可能なリンク注釈としてPDFに埋め込まれる。

**結論**: これはサイト側のコードでは解決できない、**PDF化に使うツール（プリンタードライバー vs ブラウザ内蔵のPDFエクスポート）の選択**に起因する挙動。ユーザー側に、印刷ダイアログの送信先を「Microsoft Print to PDF」ではなくブラウザ内蔵の「PDFに保存」に切り替えるよう案内することで対応した。

## 今後の進め方

1. 記事に埋め込み画像や表が多い場合の印刷レイアウト崩れがないか、実際の記事でPDF出力を目視確認する
2. 「Microsoft Print to PDF」使用時にもリンクを参照できるよう、外部リンクURLをテキスト併記する現状の対処（`::after`）で十分か、記事本文が増えてきたら再確認する
3. 必要であれば、ボタン近くに「印刷ダイアログでは『PDFに保存』を選んでください」という短い注意書きをUI上に出すことも検討する
