# progratur 立ち上げ（2026-09-14）

このドキュメントは、2026年9月14日に行った `progratur/`（学習用プログラミングリファレンスサイト）の新規構築についてまとめたものです。

## 概要

C# / Java / Python の文法・ランタイム・標準ライブラリを、具体的なコード例とともにまとめる学習サイトを新規に立ち上げた。既存の `blog/` とは別プロジェクトとして、リポジトリ直下の `progratur/` に配置している。

参考イメージは「C# & .NET リファレンス」というダーク基調・パープルアクセントの静的ドキュメントサイト（サイドバーに章立て、本文にシンタックスハイライト付きコードブロック）。

## 技術選定

- フレームワーク: **Docusaurus**（`create-docusaurus@latest` の classic テンプレートから作成）
- 3言語（C# / Java / Python）は「文法 → ランタイム → 標準ライブラリ」という共通の章立てに統一
- 最初のスコープは「骨組み全体 + C#セクションを完成させる」とし、Java / Python は骨組み（サイドバー構成とスタブページ）のみ用意して後日拡充する方針にした

### Astro（`blog/`）とDocusaurus（`progratur/`）の違い

同じリポジトリ内で `blog/` はAstro、`progratur/` はDocusaurusと、プロジェクトごとにフレームワークを使い分けている。理由を整理しておく。

| | Astro (`blog/`) | Docusaurus (`progratur/`) |
| --- | --- | --- |
| 種類 | 汎用Webフレームワーク | ドキュメント/リファレンスサイト専用フレームワーク |
| レンダリング | 既定でサーバーレンダリング（`astro.config.mjs`で`output: 'server'`＋Node adapter） | 既定でビルド時に全ページを静的HTML化（SSG） |
| UIの書き方 | `.astro`という独自テンプレート言語（JSXに似た構文＋frontmatter） | React（`.js`/`.jsx`コンポーネント） |
| コンポーネント混在 | React/Vue/Svelte等を"島"として部分的に混在可（Islands Architecture） | React専用（Docusaurus自体がReact製） |

**`blog/`がAstroな理由**: ブログは管理画面からのログイン・記事投稿・画像アップロード、Supabaseによるユーザー認証など**動的な機能**（フォーム送信・DB書き込み・セッション管理）が必要。Astroは`output: 'server'`にすればAPIルート・SSR・認証込みのアプリケーションサーバーとして動かせる汎用性がある。

**`progratur/`がDocusaurusな理由**: このサイトは「Markdownで文章を書く→サイドバー付きで読める」という**ドキュメントサイトに特化した機能**が最初から標準装備されている。

- サイドバー階層・パンくず・前後ページへのナビゲーション → `sidebars*.js`を書くだけで自動生成
- ダーク/ライト自動切替、シンタックスハイライト、複数ドキュメントツリーの共存（multi-instance docs） → 全部プリセット/プラグインで同梱

同じことをAstroでゼロから作ることも可能だが、サイドバー生成・アクティブリンクのハイライトなどを自前実装する必要があり手間が増える。ドキュメントサイトに関してはDocusaurusの方が完成度が高いため、今回はDocusaurusを選んだ。

まとめると、**Astro＝何でも作れる土台（アプリ的な機能が要る場合向き）**、**Docusaurus＝ドキュメントサイトに全振りした完成品（文章とコード例を整理して読ませることが目的なら最速）**という使い分け。

## サイト構成

```text
progratur/
├── docusaurus.config.js   … 全設定の起点
├── sidebars.js            … C#サイドバーの章立て
├── sidebarsJava.js        … Javaサイドバーの章立て
├── sidebarsPython.js      … Pythonサイドバーの章立て
├── docs/                  … C#本文（/csharp/ 配下、完成済み）
├── java-docs/             … Java本文（/java/ 配下、骨組みのみ）
├── python-docs/           … Python本文（/python/ 配下、骨組みのみ）
├── src/pages/index.js     … トップページ（3言語へのハブ）
└── src/css/custom.css     … ダーク／パープルテーマの共通スタイル
```

`docusaurus.config.js` は `presets`（classic、C#用docsインスタンス）と `plugins`（`@docusaurus/plugin-content-docs` を2回、Java用・Python用）を使い、1サイトの中に3つの独立したdocsインスタンスを共存させている。

## ファイルの呼び出し方・関連性

Docusaurusは`npm start` / `npm run build`のたびに `docusaurus.config.js` を起点として、他のファイルを芋づる式に読みに行く。

```text
docusaurus.config.js                … 起点
├─ presets[0] "classic" の docs (id: 'csharp')
│    sidebarPath: './sidebars.js'      ──▶ sidebars.js を読む
│                                           └─ items の文字列 ('syntax/if-for-switch' 等)
│                                              ──▶ docs/**/*.md の frontmatter `id:` と名前で突き合わせ
├─ plugins[0] plugin-content-docs (id: 'java')
│    sidebarPath: './sidebarsJava.js'  ──▶ sidebarsJava.js → java-docs/**/*.md
├─ plugins[1] plugin-content-docs (id: 'python')
│    sidebarPath: './sidebarsPython.js'──▶ sidebarsPython.js → python-docs/**/*.md
├─ themeConfig.navbar.items (type: 'docSidebar')
│    docsPluginId + sidebarId          ──▶ 上記3インスタンスのどれを表示するか指定
├─ theme.customCss: './src/css/custom.css' ──▶ 全ページ共通スタイル
└─ favicon / navbar.logo.src / themeConfig.image ──▶ static/img/* を参照

src/pages/index.js（"/" ページ、ファイルベースルーティングで自動登録される）
├─ <Layout>（@theme/Layout）
│    └─ 内部で useDocusaurusContext() を呼び、config の
│       navbar / footer / colorMode / favicon 等を自動的に描画する
│       （index.js側には navbar/footer のコードは一切書いていない）
├─ <Link>（@docusaurus/Link）… SPA遷移＋プリフェッチ＋壊れリンク検査の対象になる<a>代替
├─ <Heading>（@theme/Heading）… 見出しアンカー付与つきの<hN>代替
└─ href: '/csharp/intro' 等 … routeBasePath('csharp'/'java'/'python') + 各intro.mdの
                                 slug: /intro と「値として」一致させている手打ちのURL
                                 （自動解決ではないため、routeBasePathを変えたらここも直す必要あり）
```

ポイントは2つ。

1. **`@theme/`と`@docusaurus/`は実フォルダではなくエイリアス**。`@theme/`は差し替え可能な見た目コンポーネント（`node_modules/@docusaurus/theme-classic/`実体）、`@docusaurus/`はコア機能（`Link`など）を指す。webpack/rspack設定側でパス解決されている。
2. **新しいページを1つ増やす最短経路は「①`docs/`（または`java-docs/` `python-docs/`）に`.md`を置いてfrontmatterに`id:`を書く → ②対応する`sidebars*.js`の`items`にその`id`を1行追加する」の2ステップ**。片方だけだとファイルは存在してもサイドバーに出てこない「迷子ページ」になる。

（この節はREADME.mdの「ファイルのつながり」セクションと同内容。サイト側の正本はREADME.md、こちらは立ち上げ時点のスナップショットとして残す。）

## ハマった点・修正した不具合

### admonition（`:::note` 等）が生テキストのまま表示される不具合

C#の各ページに入れた `:::note タイトル` のような注記ボックスが、ビルドしても色付きボックスに変換されず、`:::note タイトル ... :::` という生のテキストがそのまま画面に出てしまう不具合があった。

**原因**: `docusaurus.config.js` に設定していた `future: { v4: true }` が、Docusaurus v4系の新しいMarkdown挙動をまとめて先取り有効化しており、その中の `mdx1CompatDisabledByDefault` フラグにより、旧来の「タイトルを `[]` で囲まない」admonition記法（`:::note タイトル`）をパースするための前処理が無効化されていた。

**対処**: 全ページの admonition 記法を新しいブラケット構文に一括変換した。

```diff
- :::note 遅延実行
+ :::note[遅延実行]
```

`docs/` `java-docs/` `python-docs/` 配下、合わせて45箇所を置換。以降このプロジェクトでタイトル付きadmonitionを書くときは `:::type[タイトル]` の形式を使う必要がある（タイトルなしの `:::note` はそのままでよい）。

### MDXがジェネリクス表記をJSXタグと誤認する不具合

見出しやadmonitionタイトルに `Dictionary<TKey, TValue>` のようなC#のジェネリクス表記を裸で書くと、MDXがこれをJSXタグとして解釈しようとしてビルドエラーになった（例: `docs/stdlib/collections.md` の `## Dictionary<TKey, TValue>`）。

**対処**: 見出し・admonitionタイトル中のジェネリクス表記はすべてバッククォートで囲んだ（`` ## `Dictionary<TKey, TValue>` ``）。コードフェンス（```csharp ... ```）内は元々MDXの解釈対象外なので問題なし。
